## Замечания, оставленные открытыми осознанно

Двадцать одно замечание реестра не входит ни в одну из двадцати четырёх задач. Каждое названо
здесь с причиной, чтобы реестр можно было сверить в конце работы и чтобы ни одно не осталось
незамеченным по недосмотру.

**Требуют решения, а не правки** — по образцу `architecture#6`, получившего собственную задачу
T14:

| Замечание | Что решать |
|---|---|
| `changelog#1` | точка отсчёта, против которой измеряется пункт журнала: измерять при написании, помечать пункт, или собирать при выпуске |
| `pr-rules#20` | момент записи в журнал изменений: до открытия PR или после проверки (уже заведено как GH-105) |
| `cpp-api-design#3` и `cpp-encapsulation#4` | владелец порядка объявления членов класса |

**Пробелы покрытия, требующие новых разделов, а не исправления существующих.** Проход по
навыку правит то, что написано; написать отсутствующее — работа другого объёма:

| Навык | Чего не хватает |
|---|---|
| `cpp-api-design` | семантика значений для публичной границы, правило «реализация в `.cpp`», полнота определения ломающего изменения, запрет `bool` в параметрах шаблона (`#1`, `#2`, `#3`, `#4`) |
| `cpp-coding` | политика обработки ошибок, многопоточность, инициализация, время жизни и висячие ссылки, целевой стандарт (`#2`) |
| `ddd` | репозиторий, фабрика, доменное событие, карта контекстов (`#2`) |
| `debugging` | откат как первый шаг, отладка по артефакту после события, санитайзеры (`#3`, `#4`, `#5`) |
| `requirements` | перечень качеств требования, идентификаторы, источник, управление изменением, словарь (`#4`, `#5`, `#6`) |
| `project-planning` | приоритет, сокращение области, перепланирование, работа с накопленным списком, шов с трекером (`#1`, `#2`) |
| `security-and-hardening` | криптография, внедрение, состязание, исчерпание ресурсов, ссылка на внешний каталог уязвимостей (`#4`) |
| `release` | процедура на ошибочный тег, предвыпуски, объект выпуска платформы, кто выпускает (`#3`) |
| `code-review-and-quality` | владелец правил читаемости: имена, размер функции, поток управления (`#8`) |
| `hook-scripts` | поведение гейта на файле вне проекта (`#8`) |

**Почему они оставлены.** Каждый пробел — новый раздел навыка, то есть работа объёмом с
отдельную задачу, и его выполнение до того, как рубрикатор из T1 применён, потребует
переписывать написанное дважды. Их место — следующая волна, после того как двадцать четыре
задачи закрыты и рубрикатор доказал применимость.

**Условие сверки.** Работа считается завершённой, когда каждое замечание реестра - и по
навыкам, и сквозное - либо закрыто задачей, либо стоит в этом списке с причиной. Замечание, не попавшее
ни туда, ни сюда, означает пропуск.
